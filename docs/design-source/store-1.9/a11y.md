## Item #2: app accessibility, investigated in the real code (read-only, nothing changed)

### Verdict
The audit is right on all three counts, with one correction on the pill.
- **Web keyboard: confirmed, and it is a WCAG 2.1.1 Level A failure.** On the web, no keyboard (or web screen reader) user can open a task's held card. Everything behind it is unreachable: rename, Break it down on an existing task, Make it tiny, Move to, Mark as a lot, reorder, Remove, Steps, and select mode with all its bulk actions.
- **Native screen readers: there is no `accessibilityActions` anywhere in `client/src`.** The hold works only through gesture pass-through.
- **Contrast: worse than "faint grey labels".** In light mode `inkFaint` can never be a text colour, because the gap to 4.5:1 is arithmetic, not taste. All bare text on Today's living sky fails in light mode, including `inkSoft` and `accent`. Small accent text on tints fails. The six Premium light themes are worst, and their check-circle rings also fail 3:1.
- **Pill correction:** at rest it does NOT cover the last task (list pad 92 vs pill top 82). The real defects: it sits on the held card's footer ("Select more" is centred, right under it), keyboard focus parks rows under it, and it is the last Tab stop on the page.

Method: WCAG relative luminance. Cards are composited at their real alpha (surfaceCard 0.92 light / 0.86 dark) over every stop of every phase of `PHASE_GRADIENT` (lib/phase.ts:24-29). The top-of-screen glow is modelled at about 0.35 effective alpha in light and 0.11 in dark (linear radial falloff). Worst case is reported. ### Evidence

**A. Web keyboard (proven from source, no guess)**
- `node_modules/react-native-web/dist/modules/usePressEvents/PressResponder.js:380`: "Long press is not supported for keyboards". `onLongPress` only fires when `event.nativeEvent.key == null`.
- PressResponder.js:66-72: Enter is the only valid key on `role=checkbox` (Space only counts on button roles). So Enter ticks a row and Space does nothing (and scrolls the page).
- Rows ARE Tab-reachable (Pressable gets tabIndex 0, `exports/Pressable/index.js:118-123`). They can be ticked but never opened.
- `react-native-web` does not forward `accessibilityActions` at all, so a native-only fix leaves the web broken.
- The only door is `onRowLongPress` (today.tsx:1418-1420). Select mode is reachable only from a held card's Select more (today.tsx:1404, 1551). The code's own comment at today.tsx:3250 says "The long-press is the only door to half the app".
- Long-press is used only by TaskRow (Today x3 call sites, ours-list.tsx:862), so one component fix covers every surface.
- Hold-hint coachmark (today.tsx:3250-3264): its `accessibilityLabel` "Got it, hide this tip" replaces the visible tip, so screen-reader users never hear "Hold a task for more…".
- No app-wide `:focus-visible` style. The landing page has one (landing-page.ts:381). The app relies on the browser's default ring, which is fine except where a parent clips it (see K6).

**B. Native screen readers**
- RN 0.85 maps `accessibilityActions` name `longpress` to `ACTION_LONG_CLICK` on Android (`ReactAccessibilityDelegate.kt:566`), which makes TalkBack's double-tap-and-hold and Actions menu work. On iOS Fabric every action becomes a labelled VoiceOver custom action in the Actions rotor (`RCTViewComponentView.mm:1512-1535`).
- Today, TalkBack double-tap-and-hold on a JS-only `onLongPress` is unreliable. Treat that as likely broken and confirm in the build-test loop.
- Focus loss: opening the card swaps TaskRow's render branch (TaskRow.tsx:471). The focused row unmounts, so web focus drops to `<body>` and VoiceOver/TalkBack focus jumps. Nothing moves focus into the card or back to the row on close. No Escape, `onAccessibilityEscape` or Android back closes the card (no BackHandler in today.tsx).

**C. Pill geometry (CaptureSheet.tsx:47, 61-72)**
- Pill: 48 tall, 96 wide (124 with a draft), centred, bottom edge at max(34, inset), so its top is 82 above the foot on web and notchless phones.
- List end pad: `restingListPad` = 8+52+max(inset-2, 32) = 92. The last row clears at rest. Good.
- Held card on web: TaskRow.tsx:209-215 `scrollIntoView({block:'nearest'})` stops with the card's bottom at the scroller's bottom edge. The scroller fills the screen and its padding is content padding, not scroll-padding. So the 52-tall shelf lands in the pill's band (34..82) and the centred "Select more" (terminal row, TaskRow.tsx:496-519) can be fully hidden. That fails WCAG 2.4.11 for keyboard focus, and the pill eats taps meant for it.
- Native: no scroll at all ("no-ops there", TaskRow.tsx:206), so the same overlap happens whenever a low row is held.
- Keyboard Tab on web: the browser scrolls the focused row to the bottom edge, under the pill. That is a partial obscure (2.4.11 AA passes, AAA fails).
- Focus order: CaptureSheet renders after the ScrollView (today.tsx:3555), so "Add a task" is the LAST Tab stop, after every row, the Later rows and the footer links.
- Done well, leave alone: open lands on the heading, close returns to the pill (CaptureSheet.tsx:177-196), the shut panel is `inert`, the list is `inert` while the panel is open, and Escape and Android back close the panel.
