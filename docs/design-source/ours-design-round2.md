# Handoff: DoubleDone "Ours" — complete design (rounds one + two)

## Overview
The full Ours design in one package: round one (the door — pairing, code, resting, closed) and round two (the room — the shared list, the bridges, repeating, the guards, the Today door, and the Check-for-updates sub-brief). One combined board: `DoubleDone Ours Complete.html` (round two's frames first, round one's beneath, newest work on top).

## The model (decided)
One shared list, exactly two people, joined by a six-character code (`K7M-P4Q`, no 0/1/I/L/O) bound to one email, valid once, for a day. Self-chosen names only. Nothing touches your Today unless you bring it there. Leaving freezes the list for both; nothing is deleted. Resume is the handshake again, never unilateral, no email re-ask.

## Navigation
- Menu → Ours: discovery, and the only entry when no list exists (no funnel on Today).
- Today's door row ("Ours · {name} ›", after the day's list, before the tools card): one tap to the shared list. Never a number on it. Absent when no list exists.
- The shared list's header line ("Kept with {name}") → the management screen (rename self, archive, leave).
- Management screen foot → Closed lists (the archive) → a frozen list → resume or delete.

## The six laws → design answers
1. **No attribution, including pending state.** Rows are Today's to the pixel; done is sage and anonymous; no initials, no "done by", no mutual-confirm anywhere. Pulling leaves no trace the other person can read.
2. **No counting.** No number on the door, ever; no progress over two people; no "2 changes" line.
3. **No identifiers.** Only the code-maker sees the address they typed; the joiner sees a chosen name only.
4. **Sealed room.** Nothing lists lists' company; the archive shows purpose + closed-month only.
5. **Second seat may decline.** Equal doors; promise-first join screen; unhurried exits; resume-decline is silent (the code lapses, indistinguishable from never-seen).
6. **Never shame, doubled.** No row age, no "waiting on you"; finality inscriptions withheld on Ours (done is provisional; either person unticks with one tap).

## Round one — the door (accepted positions)
- **Naming first**: purpose → your name → their email (the sharp edge last, beside the code it binds).
- **Waiting is not a screen**: folded into the code screen ("you can close this — the list opens the moment they join"). The client cannot know if a code is still alive; nothing shows a countdown or greys a dead code.
- **Leaving stays visible**: resting screen's shelf, danger-soft, every visit; confirm card states the literal truth (freezes, both keep reading, nothing taken).
- **The word stays Ours.**
- Key frames: nothing-yet (two equal doors), what's-it-for (skip is first-class), two-small-things (email care copy: "worth a slow read. They'll never see yours."), the code (40px, share/copy/fresh-code), joined-yours / joined-theirs (exits at the moment of doubt), resting (D7), closed (D8: "still here, nothing taken, nothing moved" — all literally true), join-by-code (one field, never OTP boxes), the Today door.

## Round two — the room
**A · The shared list**
- At rest: Today's rows; "shared" is one header line ("Kept with Alex"). No weight gauge, no day tools, no motto — plainer than Today on purpose.
- **The quiet wash** (changed rows): accentSoft tint + slightly stronger border on rows changed since your last open. Static (nothing animates because of the other person), names nobody, counts nothing, gone next open. Argued FOR: it bounds the re-reading/checking loop.
- Held card, shared: **Bring to my Today** in the hero seat (sub "a copy, on your list") · Repeat… (the one repeating drawer) · the rail · More → Remind me (local, leaks nothing) · shelf: Close / Select more / Remove (→ Recently removed). Gone: AI shapers, Mark as a lot, Pin.
- Empty: "Nothing here yet. Whatever either of you adds, you both see." + capture bar speaking the list's name. No nudges.

**B · The bridges** (nothing crosses without a person choosing it)
- Pull: your Today copy carries a faint "· Ours" suffix (your room only). The shared row is untouched — any marker would be attribution through the side door.
- Your tick: closes both; enters YOUR Lookback; from the other side it is simply done, nobody signed it.
- **Their tick when you'd pulled it**: your copy is never struck through, never enters your Lookback. In its place, this visit only, a dashed sage rest-note: "Handled on Ours. It's off your day." Gone next open. (Silent vanish reads as "did I delete that?"; strike-through would be a lie.)
- Share your own task to Ours: personal held card fold gains "Share to Ours" (only when a live list exists). 500-char cap handled honestly before the copy: "Ours keeps titles shorter. This one will be trimmed to fit."

**C · Repeating**
- Shared repeating row: periwinkle ↻; the day records THAT it was done, never by whom; untick is one tap (load-bearing; the reason two-party confirm was refused).
- Cadence: the same repeating drawer as home — one cadence surface in the app. Ours-specific line: "You'll both see it on its day." Commit button names the cadence.
- **Unreadable cadence (newer build set it): SHOWN, never hidden** — row inert with "On a rhythm this version can't read yet. It's safe, and it'll appear on its days after an update." Hidden would make each person think the other deleted it.

**D · The guards**
- Recently removed: folded at the list's foot; dimmed rows + Restore; seven days; names nobody.
- Frozen list in use: read-only rows, capture bar gone, each undone row keeps ONE action ("Bring over"). "Reopen together…" (mauve) above "Delete this list for good" (danger-soft, last, alone).
- **Delete window (the app's one irreversible action)**: deletion commits when the screen closes. "This list is going. It leaves for good when you close this screen. Until then, nothing has been told to anyone, and one tap keeps it." Keep it = the only button. No countdown (a visible timer is a pressure device). An undo toast would be a lie; this isn't.
- Archive ("Closed lists"): quiet rows, purpose + closed-month, readable forever ("Put it away" tucks here; supersedes the build's destructive forget_pair).
- Resume: offering mints a code (no email re-ask); **being asked** is the delicate frame — "Sam would like to open this list again. … saying nothing costs nothing: the offer lapses quietly on its own." Decline renders nothing on the other side.
- Solo-leave (nobody joined): "Nobody ever joined this one. Close it and it's simply gone." No freeze theatre.
- Report-closed: renders EXACTLY as ordinary closed, by design — any distinguishing mark would tell someone they were reported.

**E · The door** — short name one line; 40-char names wrap, never truncate; unnamed list reads just "Ours"; no row when no list.

**F · Check for updates** (recommendation accepted)
- Settings absorbs the version line: "v1.2.0 (11) · Up to date" (sage fact, not a control) / web: "A newer version is ready" + [Reload to get it] + "Anything you were typing is kept." (true — drafts persist) / native: "This build is getting old" + [Open the App Store] + "Your lists stay exactly as they are."
- The rare mention: fourth rung on the rested ladder (one at a time by construction), gated two-minors-or-major behind, once a fortnight. Reshaped as an offer FOR them: "The newer one can read everything your person sets, rhythms included." Not now costs nothing, is never remembered.
- The honest gap stands: never-closers meet it only in Settings — interrupting someone who never closes a day would be worse.

## Language armor (54 strings, adversarial pass done)
Design to German, not English (buttons + the two question titles). Error slots hold three comfortable lines without the screen jumping (join-throttle explanation is the sizing case). French non-breaking space before ?/!. "Your person" is a locked transcreation, inline in six strings, width never assumed. Names + list names: user-typed, 40 chars, wrap, never truncate. The share message (~200 chars EN, longer DE) leaves the app; the offering screen must not imply something short.

## Build seams (needed, known)
1. Self-rename RPC (pair_members has no update policy by design; needs a definer RPC scoped to auth.uid()).
2. joined_at/created_at returned on membership read ("Kept with Alex · since June").
3. "Put it away" = tuck (archive), replacing destructive forget_pair.
4. The Today door + Menu entry (build currently has a Settings placeholder).

## Token usage

The quiet wash: accentSoft at low alpha (light #F1E7EC on white; dark rgba(198,139,160,0.09) with border rgba(198,139,160,0.32)).
